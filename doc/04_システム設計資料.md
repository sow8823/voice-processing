# システム設計資料

## 1. システムアーキテクチャ

### 1.1 全体構成

本システムは、Webブラウザ上で動作するクライアントサイドアプリケーションとして設計されています。主要なアーキテクチャコンポーネントは以下の通りです：

```
+-------------------------------------+
|            ブラウザ環境              |
|  +-------------------------------+  |
|  |        Vue.js アプリケーション    |  |
|  |  +------------+  +---------+  |  |
|  |  |   UI層     |  |  状態管理 |  |  |
|  |  | (Vuetify)  |  |  (Vue)  |  |  |
|  |  +------------+  +---------+  |  |
|  |          |            |       |  |
|  |  +---------------------------+  |  |
|  |  |      ビジネスロジック層     |  |  |
|  |  | (JavaScript/TypeScript)   |  |  |
|  |  +---------------------------+  |  |
|  |          |            |       |  |
|  |  +------------+  +---------+  |  |
|  |  | WebAudio   |  |  WASM   |  |  |
|  |  |    API     |  | モジュール |  |  |
|  |  +------------+  +---------+  |  |
|  +-------------------------------+  |
|          |                |         |
|  +-------------+  +----------------+ |
|  | マイク入力   |  | キャンバス出力  | |
|  +-------------+  +----------------+ |
+-------------------------------------+
```

### 1.2 技術スタック

- **フロントエンド**:
  - Vue.js 3 (Composition API)
  - TypeScript
  - Vuetify 3 (UIコンポーネント)
  - Web Audio API (音声処理)
  - Canvas API (グラフィック描画)

- **バックエンド処理**:
  - WebAssembly (Rust)
  - pitch_detection クレート (McLeod法ピッチ検出)

- **ビルド/開発ツール**:
  - Vite (開発サーバー、ビルドツール)
  - wasm-pack (Rust→WASM変換)

```

│   │   ├── RealtimeInput.vue (molecules)
│   │   ├── RecordPlayback.vue (molecules)
│   │   │   ├── RecordControls.vue (atoms)
│   │   │   ├── PlaybackControls.vue (atoms)
│   │   │   └── RecordingsList.vue (molecules)
│   │   └── FileInput.vue (molecules)

│   │       └── PlaybackControls.vue (atoms)
│   ├── PitchCanvas.vue (atoms)
```

- 子コンポーネントへのデータ（ピッチ、周波数データ）の受け渡し
- ユーザーインタラクション（音声処理開始ボタンなど）の処理

#### 2.2.3 AudioProcessor.vue (organisms)
- 音声処理の共通ロジックを提供するサービスコンポーネント
- マイク入力の取得と音声ストリームの処理
- 録音機能の実装
- 音声ファイルの読み込みと再生
- WebAudio APIとWASMモジュールの連携
- 分析データの生成と提供

#### 2.2.4 AudioInputSelector.vue (molecules)
- 音声入力モードの選択インターフェース
- タブ切り替えによるモード選択
- 各入力モードのコンポーネントのコンテナ

#### 2.2.5 RealtimeInput.vue (molecules)
- リアルタイム音声入力モードのUI
- マイク入力の開始/停止制御

#### 2.2.6 RecordPlayback.vue (molecules)
- 録音と再生モードのUI
- 録音コントロールと再生コントロールの管理
- 録音リストの表示と管理

#### 2.2.7 FileInput.vue (molecules)
- ファイル入力モードのUI
- ファイル選択と再生コントロールの管理

#### 2.2.8 RecordControls.vue (atoms)
- 録音の開始/停止ボタン
- 録音時間の表示

#### 2.2.9 PlaybackControls.vue (atoms)
- 再生/一時停止/停止ボタン
- 再生位置スライダー
- 再生時間表示

#### 2.2.10 RecordingsList.vue (molecules)
- 保存された録音のリスト表示
- 録音の選択、削除機能

#### 2.2.11 FileSelector.vue (atoms)
- ファイル選択ボタンとドラッグ＆ドロップエリア
- 選択されたファイル情報の表示

#### 2.2.12 PitchCanvas.vue (atoms)
- ピッチ検出結果の視覚化

- ピッチインジケーターの描画

#### 2.2.13 SpectrumCanvas.vue (atoms)
- 周波数スペクトルの視覚化

## 3. データフロー

### 3.1 音声処理フロー

#### 3.1.1 リアルタイム入力モード
```
マイク入力 → MediaStream → AudioContext → AnalyserNode
    → Float32Array/Uint8Array → WASM処理（ピッチ検出）
    → 分析結果 → 各種Vueコンポーネント → キャンバス描画
```

#### 3.1.2 録音モード
```
マイク入力 → MediaStream → AudioContext → MediaRecorder
    → 音声データチャンク → Blob → IndexedDB保存
    → 録音リスト表示
```

#### 3.1.3 録音再生モード
```
IndexedDB → Blob → AudioBufferSourceNode → AudioContext → AnalyserNode
    → Float32Array/Uint8Array → WASM処理（ピッチ検出）
    → 分析結果 → 各種Vueコンポーネント → キャンバス描画
```

#### 3.1.4 ファイル入力モード
```
ファイル選択 → File → AudioContext.decodeAudioData → AudioBufferSourceNode
    → AudioContext → AnalyserNode → Float32Array/Uint8Array
    → WASM処理（ピッチ検出） → 分析結果 → 各種Vueコンポーネント → キャンバス描画
```
#### 3.1.5 リアルタイム処理フロー詳細
1. ユーザーが「音声処理を開始」ボタンをクリック
2. `navigator.mediaDevices.getUserMedia()`でマイク入力を取得
3. WebAudio APIで音声ストリームを処理
   - `AudioContext`の作成
   - `AnalyserNode`の設定
4. 定期的に音声データを取得
   - 時間領域データ（`getFloatTimeDomainData`）
   - 周波数領域データ（`getByteFrequencyData`）
5. 時間領域データをWASMモジュールに渡してピッチ検出
6. 検出結果と周波数データを各コンポーネントに渡す
7. 各コンポーネントでデータを視覚化

#### 3.1.6 録音処理フロー詳細
1. ユーザーが「録音開始」ボタンをクリック
2. `navigator.mediaDevices.getUserMedia()`でマイク入力を取得
3. `MediaRecorder`を使用して録音を開始
4. 録音データを`dataavailable`イベントで取得
5. 録音データをBlobとして保存
6. 録音メタデータ（タイムスタンプ、長さなど）をIndexedDBに保存
7. 録音リストを更新

#### 3.1.7 再生処理フロー詳細
1. ユーザーが録音リストから項目を選択して「再生」ボタンをクリック
2. IndexedDBから録音データ（Blob）を取得
3. `AudioContext.decodeAudioData()`でBlobをデコード
4. `AudioBufferSourceNode`を作成して再生
5. `AnalyserNode`を接続して音声データを分析
6. 再生位置を定期的に更新
7. 分析結果を各コンポーネントに渡して視覚化

#### 3.1.8 ファイル入力処理フロー詳細
1. ユーザーがファイル選択またはドラッグ＆ドロップでファイルを選択
2. File APIでファイルを読み込み
3. `AudioContext.decodeAudioData()`でファイルをデコード
4. `AudioBufferSourceNode`を作成して再生
5. `AnalyserNode`を接続して音声データを分析
6. 再生位置を定期的に更新
7. 分析結果を各コンポーネントに渡して視覚化
7. 各コンポーネントでデータを視覚化

### 3.2 状態管理

現在のシステムでは、以下の主要な状態を管理しています：

- `audioMode`: 現在の音声入力モード（'realtime', 'record', 'file'）
- `currentPitch`: 現在検出されているピッチ（Hz）
- `frequencyData`: 周波数スペクトルデータ（Uint8Array）
- `isProcessing`: 音声処理中かどうかのフラグ
- `isRecording`: 録音中かどうかのフラグ
- `isPlaying`: 再生中かどうかのフラグ
- `recordingTime`: 現在の録音時間（秒）
- `playbackTime`: 現在の再生位置（秒）
- `totalDuration`: 再生中のファイル/録音の総時間（秒）
- `recordings`: 保存された録音のリスト
- `selectedRecording`: 現在選択されている録音
- `selectedFile`: 現在選択されているファイル

これらの状態は、VoiceVisualコンポーネントとAudioProcessorコンポーネントで管理され、props経由または状態管理ライブラリを通じて子コンポーネントに渡されます。

## 4. WASM連携設計

### 4.1 Rustモジュール構造

```
pitch_detection/
├── Cargo.toml
└── src/
    └── lib.rs  // WASMエクスポート定義
```

### 4.2 WASM-JavaScript連携

- `wasm-bindgen`を使用してRustとJavaScriptの橋渡しを実現
- `McLeodPitchDetector`クラスをJavaScriptから利用可能に
- 主要メソッド：
  - `new(buffer_size, padding)`: 検出器の初期化
  - `detect_pitch(audio_buffer, sample_rate, power_threshold, clarity_threshold)`: ピッチ検出

### 4.3 ピッチ検出アルゴリズム

McLeod法（自己相関関数に基づくピッチ検出アルゴリズム）を使用：

1. 入力音声の自己相関関数（NSDF）を計算
2. NSFFのピークを検出
3. 最も高いピークに対応する周波数をピッチとして返す
4. パワー閾値と明瞭度閾値を使用してノイズや無音状態を除外

## 5. 描画処理設計

### 5.1 共通描画パターン

各キャンバスコンポーネントは以下の共通パターンで実装：

1. キャンバス要素への参照を取得（`ref`）
2. 描画関数を定義（例：`drawPitchIndicator`、`drawFrequencySpectrum`、`updateHeatmap`）
3. 以下のタイミングで再描画を実行：
   - コンポーネントのマウント時
   - プロパティ（ピッチ、周波数データ）の変更時
   - テーマの変更時
   - キャンバス要素の変更時

### 5.2 最適化戦略

- `requestAnimationFrame`を使用した効率的な描画更新
- キャンバスサイズの最適化（描画領域に合わせたスケーリング）
- 必要な部分のみを再描画（差分更新）
- WebGLの活用検討（将来的な拡張として）

## 6. データ永続化設計

### 6.1 IndexedDBスキーマ

録音データと関連メタデータを保存するためのIndexedDBスキーマ：

```
Database: VoicePitchAnalyzerDB
  ObjectStore: recordings
    Key: id (auto-increment)
    Indexes:
      - timestamp (Date)
    Properties:
      - id: number (primary key)
      - name: string (録音名)
      - timestamp: Date (録音日時)
      - duration: number (録音時間、秒)
      - audioBlob: Blob (音声データ)
      - format: string (音声フォーマット、例: 'audio/webm')
```

### 6.2 ファイル処理

外部音声ファイルの処理方法：

1. File APIを使用してファイルを読み込み
2. AudioContext.decodeAudioDataでデコード
3. メモリ内でAudioBufferとして処理
4. 必要に応じてキャッシュ（SessionStorage）

## 8. 技術的課題と解決策

### 8.1 現在の課題

- **ブラウザ互換性**: 異なるブラウザでのWebAudio API実装の違い
- **モバイル対応**: モバイルデバイスでのパフォーマンス最適化
- **メモリ使用**: 長時間の音声処理におけるメモリリーク防止
- **精度向上**: ノイズの多い環境でのピッチ検出精度向上
- **録音フォーマット**: ブラウザ間での録音フォーマットの違いへの対応
- **大容量ファイル**: 長時間の録音や大きな音声ファイルの効率的な処理

### 8.2 解決アプローチ

- **ポリフィル/シム**: ブラウザ間の互換性問題に対処
- **プログレッシブエンハンスメント**: 基本機能を確保しつつ拡張機能を提供
- **メモリプロファイリング**: 定期的なメモリ使用状況の監視と最適化
- **フィルタリングアルゴリズム**: 前処理でのノイズ除去強化
- **フォーマット変換**: 必要に応じて録音データのフォーマット変換
- **チャンク処理**: 大きなファイルをチャンクに分割して処理
- **ストリーミング**: 大きなファイルのストリーミング処理

## 9. セキュリティ考慮事項
